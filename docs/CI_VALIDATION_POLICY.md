# 分层验证与 CI 效率策略

日期：2026-10-09。用户已同意分层验证方向；本文记录后续工作流改造契约，尚未改变 GitHub 必需检查或现有发布门槛。

## 目标与边界

让低风险修改快速取得可靠反馈，避免每个中间提交重复完整跨平台构建、双版本安装包及恢复原型。效率来自消除无关和重复工作，不来自删掉失败测试、弱化安全检查或把未执行的测试标为通过。

分类依据是行为、依赖和受影响平台，不是修改行数。证据不足、公共依赖变化或分类无法确定时，升级到更完整验证。修改文档中的可执行命令、发布契约或安全操作流程，不自动视为普通文字修改。

## 验证层级

1. 文档与纯展示文字：差异/仓库卫生、适用的链接或文档检查；涉及编译内嵌文本时加受影响包构建。不运行无关安装恢复矩阵。
2. 低风险诊断与平台局部修改：格式、受影响包 Clippy、定向回归和受影响平台原生测试/必要构建。只保留错误上下文且不改变控制流、授权、缓存布局、状态或错误类别的诊断修改可走此层；必须用测试证明这些性质，不能只凭文件名判断。
3. 普通行为与公共组件修改：受影响功能完整回归，检查直接和间接消费者；跨平台公共逻辑在三平台验证。升级依赖、工具链、feature 或构建配置时扩大相应覆盖。
4. 更新安全、安装与恢复行为修改：完整保留受影响的签名/信任根、URL/TLS、序列防回退、ACL/缓存、安装身份、事务/多实例、退出等待、健康确认及恢复故障矩阵。安装器、助手协议、文件替换、快捷方式和卸载身份变化必须执行相关原生安装恢复测试。真实 GUI 门槛仍独立记录，CI 不代替实机验收。
5. 正式发布与对外更新能力启用：对确切发布源码执行完整跨平台回归、平台构建/打包和适用安装恢复矩阵；校验确切资产、签名清单、大小/SHA-256、来源及公网指针。技术预览也必须完成其明确承诺的范围，不冒充正式发布或实机已通过。

所有层级保留仓库卫生与秘密检查。改动涉及多个层级时取覆盖其风险的组合；不以“只是小改动”降低层级。

## 工作流改造要求

- 先实现可测试的改动分类器，比较 PR 的正确基线与当前 head，而非只看最后一个提交。未知路径、分类失败、依赖/安全边界变化应保守扩大覆盖。
- 分开快速反馈、平台验证、昂贵打包/恢复和发布部署；避免三个系统重复与平台无关的同一脚本测试。
- 保留稳定的汇总门禁。整个门禁工作流必须触发，汇总任务始终运行，并核实分类和所有应执行任务确实成功；不能让路径过滤造成 required check 永久 pending，也不能把失败、取消或缺失任务当作成功。
- 任务未执行时说明分类理由，不能把 skipped 当作已通过测试。显式完整验收入口必须可以强制执行全部适用检查。
- 有针对性测试证明分类边界和汇总门禁：普通文字、平台局部、公共依赖、安全逻辑、工作流自身、混合修改、未知路径，以及失败/取消/缺失任务均覆盖。
- CI 工作流、发布权限、OIDC、受保护环境、签名或验收规则修改需要对应工作流与安全回归，不能自行归入“文档”或“轻量配置”。
- 在新门禁验证可靠并完成审查前，不取消或改名现有四项必需检查。分支保护调整属于明确的单独步骤，不使用管理员绕过来完成迁移。

## 避免重复工作

- 本地先做定向验证，将同一问题的相关修复集中提交，避免每个诊断猜测都重新触发昂贵全量链路。
- 缓存按操作系统、架构、固定工具链、锁文件及构建配置隔离；缓存不是测试证据，信任材料和私钥不得进入共享缓存。
- 成功构建的安装包由后续部署直接消费，不为上传再构建一次。资产必须绑定 source SHA、run/attempt、配置与哈希；新源不能冒充旧构建。
- 跨 SHA 复用验证证据只能通过显式、经审查的相关输入等价性规则实现，并在门禁报告实际测试 SHA 与当前 SHA。无法证明等价时重跑；当前固定 QA source/run 规则保持不变。
- 经验证后可取消被新提交取代的普通 PR 验证；不自动取消正在安装、恢复、发布或写 latest 的事务，不覆盖不可变对象。失败恢复只消费已核验的相同对象。
- 监控按用户约定低频查询，无变化时安静结束当轮，不持续监听、不重复读取整段成功日志。

## 耗时与验收

分别记录排队、依赖/编译、测试、打包、OSS 上传、公网验证的耗时。上传重试或权限阻塞不是 CI 测试耗时；应定位对应阶段，不用削减测试解决上传问题。

快速路径以数分钟反馈为优化目标，不承诺固定完成时间。改造完成后用实际代表性改动对比耗时，检查分类没有漏测，且完整发布路径和必需门禁仍能拒绝坏签名、错误资产、未通过测试及错误来源。

## 执行顺序

1. 保存本策略与 AGENTS.md 入口（本次完成）。
2. 单独提出工作流改造，按上述分类和门禁边界补测试；不混入当前 Windows 诊断包交付。
3. 保留旧必需检查，验证新路径及耗时后审查迁移分支保护。
4. 再启用优化后的日常验证；对外发布继续执行完整的适用验收。
